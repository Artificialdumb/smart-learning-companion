# 三组对照评价方案（教师独立评价）

## 目的

验证“以评分点为证据、再加错因追问与补学路径”是否让教师认为依据更充分、建议更可执行。评价对象是**依据与建议的呈现**，不是诊断准确率，也不是教学效果。在完成本评价并公开结果之前，对外只描述系统做了什么，不宣称“诊断更准”“效果领先”。

## 三组条件

同一批次、同一学生、同一测验、同一指标，只改变呈现的信息：

| 代号 | 名称 | 教师看到的内容 |
|---|---|---|
| A | 仅按得分率推荐 | 指标得分率、有效作答题数；得分率低于 60% 时推荐一份该指标材料，否则“可继续” |
| B | 增加评分点依据 | 系统诊断发现，引用的作答记录、题目、最终作答、失分评分点和出错步骤；按证据生成的学习活动、分步提示和复查条件 |
| C | 再增加追问和补学路径 | B 的全部内容，加上错因追问题目（标出与失分评分点相关的维度）和前置知识补学路径 |

## 材料生成

```sh
python -m app.cli build --source data/赛题资料包 --db outputs/eval.sqlite3
python -m tools.ablation packet --db outputs/eval.sqlite3 --run-id <批次编号> --out outputs/对照评价 --per-kind 6 --seed 1
```

- 按活动类型（针对性巩固、变式练习、补充观察）分层抽样，每类最多 `--per-kind` 个案例，随机打乱。
- 每个案例的三种呈现以“甲、乙、丙”随机排序；`key.json` 记录对应关系，**只由组织者保存，不发给评分教师**。
- 发给教师：`评价材料.md`（或打印版）与 `评分表.csv`。合成数据示例见项目 `output/对照评价材料-合成示例/`。

## 评分流程

1. 评分教师至少 2 名，不参与本系统开发，事先不看系统演示。
2. 每位教师独立完成，不讨论、不交换评分表。
3. 每个版本按三项打 1–5 分：诊断依据是否充分、可核对；建议是否具体、可直接执行；建议是否针对该生的实际错误。另标注“是否存在错误或误导”，可写备注。
4. 收回后运行：

```sh
python -m tools.ablation analyze --key outputs/对照评价/key.json --ratings 教师1.csv 教师2.csv
```

## 统计口径

- 报告每组各评分项的均值与评分条数、误导标注比例、评分人之间相差不超过 1 分的比例。
- 配对比较 B 对 A、C 对 B：**以案例为单位**，同一案例先对多名教师的评分取平均，再统计胜/负，用双侧精确符号检验，平局剔除。不把“教师 × 案例”当成独立样本。
- 同时报告胜负计数与 p 值；案例数少时 p 值不稳定，以计数和教师备注为主。

## 已知局限

1. **盲法不完全**：A 版信息明显更少，教师可能猜出哪一版是“仅得分率”。盲法只能减少、不能消除这种偏差。
2. **补充观察类案例中 B 与 C 可能完全相同**（没有失分，就没有追问），这类案例只用于检验评分一致性，不用于 C 对 B 的结论。
3. 评分是教师的主观判断，可以说明“教师认为依据更充分、建议更可执行”，不能说明学生成绩提高或诊断更准确。
4. 赛题数据只有模拟学情，案例来自同一批次；结论不能外推到真实课堂。
5. 评价尚未开展。目前只有工具和合成示例，**没有任何教师评分结果**。

## 对外表述建议

- 可以说：系统提供评分点级证据、错因追问和补学路径；已设计三组对照的教师盲评方案，并提供可复现的评价材料生成与统计工具。
- 完成评价后可以说：在 N 个案例、M 名教师的独立评价中，B 相对 A 在某评分项上的胜/负为 x/y。
- 不应说：诊断准确率达到某值；教学效果领先；优于其他系统。
