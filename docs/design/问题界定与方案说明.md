# 智慧学伴 · 问题界定与方案说明

> 本文说明项目问题、分析范围、技术路线、实施进度与后续计划。字段口径见 [数据契约](../interfaces/contracts.md)，调用与演示步骤见 [联调说明](../interfaces/integration.md)。

## 1. 背景

七年级数学的代数部分（代数式与整式、一元一次方程与二元一次方程组、一元一次不等式与不等式组）是后续学习的基础。日常测验产生大量作答，但教师通常只能看到总分，难以回答三个问题：

1. **这名学生具体错在哪里？** 是概念没懂、计算失误，还是没读懂条件？证据在哪一题、哪个评分点、哪一步？
2. **两个班的差异是真的吗？** 两班做的题、交卷人数不同，直接比平均分会得出错误结论。
3. **下一步练什么？** 建议要能对应到课程标准、教材页码和题库里的具体材料，并且教师能改。

赛题资料包提供了课程要求、题目与材料（含评分点、参考答案）、模拟学生名册、测验节点、作答记录（含修订版本和评分状态）、2022 版课程标准和教材 PDF。数据本身存在真实场景中的质量问题：同一作答多次修订、待评分、未作答、分数越界、评分点合计与总分不一致、重复记录等。

## 2. 用户与使用场景

| 用户 | 场景 | 需要什么 |
|---|---|---|
| 任课教师 | 测验后查看学生和班级情况、布置补学 | 有依据的诊断、可比的班级数据、可修改的学习计划 |
| 学生 | 查看本人诊断、完成错因追问、按路径补学 | 看得懂的失分原因、针对性的小题和材料 |
| 教研/管理 | 复核数据质量、导出成果 | 可追溯的批次、质量报告、成果包 |

## 3. 问题界定

### 3.1 核心任务

| 任务 | 输入 | 输出 | 判定原则 |
|---|---|---|---|
| T1 数据接入与质量控制 | 原始 CSV、人工复核决定 | 最新有效作答、质量报告 | 每个作答事件只取最新修订；有问题的记录进入复核，不静默丢弃 |
| T2 个人诊断 | 有效作答、课程目录 | 每名学生 × 每个测验节点 × 每个指标的诊断 | 每条结论都必须能回查到作答记录、评分点和步骤 |
| T3 掌握度估计 | 学生截至当前节点的全部有效作答 | 得分比例指数、区间、有效作答条数、等级 | 少于三条作答时标记“证据不足”，按区间和证据条数安排补测 |
| T4 班级对比 | 两班有效作答、完整名册 | 共同题范围内的覆盖与得分比较、共性失分 | 只在两班都有有效作答的共同题上比较，明确分母 |
| T5 学习建议 | 诊断、题库与材料 | 按证据排序的学习活动 | 失分优先巩固；多次满分才给变式；证据不足先补充观察；提示不得泄露答案 |
| T6 教师调整 | 教师修改 | 新版本计划，保留原计划 | 校验资源适用范围与提示文字；并发修改只有一个成功 |
| T7 错因追问与补学路径 | 失分证据 | 针对失分评分点的追问小题、前置知识补学顺序 | 追问结果关联原题证据，补充记录独立保存 |
| T8 成果导出 | 批次 | 成果包（JSON + 说明文档） | 可从成果包重新构建初始分析 |

### 3.2 分析范围

系统使用赛题提供的已有评分，覆盖七年级代数三个主题、九个观察指标。诊断与提示由规则生成，可选本地模型在经过规则校验的候选材料中选择资源。扩展学科时同步补充课程指标、题组、定位规则和测试。

部署方式包括本机演示与账号授权的共享服务。批次保存完整生效规则和追问题组，教师依据原题证据与补充作答确认学习需求。

### 3.3 评价方式

| 维度 | 指标 | 当前做法 |
|---|---|---|
| 正确性 | 统计口径与人工核对一致 | 合成数据与边界用例的单元测试；赛题数据回归测试 |
| 可追溯 | 结论可回查比例 | 每条发现带 `record_id`、评分点、步骤号；批次带源文件 SHA-256 |
| 稳健性 | 异常数据不导致错误结论 | 冲突修订、越界分数、评分点不一致均有测试 |
| 可用性 | 教师完成“看诊断→调计划→导出”的步骤数 | 网页三视图：个人、班级、课程材料 |
| 安全合规 | 越权访问被拒绝 | 学生只看本人，教师只看授权班级；共享服务强制 HTTPS |

## 4. 技术路线

```
赛题资料包 CSV / PDF
      │  A：目录构建 + 导入校验 + 人工复核（app/catalog, app/ingestion）
      ▼
标准化批次（manifest / catalog / students / responses）──── 源文件 SHA-256、批次号
      │  B：个人诊断 + 掌握度估计 + 班级对比（app/diagnosis, app/class_analysis）
      ▼
诊断结果 ──► 学习建议（app/recommendations，可选本地模型在候选中选择）
      │
      ▼  C：SQLite 批次存储、教师调整、追问（app/storage）
FastAPI 接口 + 网页（app/web） ──► 成果包导出（app/cli export）
```

### 4.1 关键方法

- **证据化诊断**：以评分点为最小证据单位。失分评分点生成“针对性巩固”，得分评分点生成“已掌握表现”，无有效作答生成“补充观察”。简单整式题中，过程末行与最终填写只差符号时，自动定位到出错步骤。
- **掌握度（得分比例指数）**：每条有效作答记一次证据，按得分比例计入 Beta(1,1) 先验，累计该生在当前及更早测验节点、该指标下的作答，得到平滑均值和 90% 区间。有效作答少于 3 条标记“证据不足”；区间下限达到阈值才判为“已掌握”。早期版本按分值单位计证据，同一作答放大分值就会让区间变窄；模拟显示 10 个评分点时 90% 区间实际覆盖率只有约 50%，现已改为按作答计（覆盖率 96%–99%，偏保守）。该指数描述经平滑的得分比例，结合证据条数与区间阅读，详见 [掌握度证据权重说明](../evaluation/掌握度证据权重说明.md)。
- **按失分点追问**：根据失分评分点的评分标准把错误归到概念、计算或条件理解维度，并把对应维度的追问排在最前；若诊断已定位出错步骤，还会用学生本人的过程与最终填写生成一道核对小题。
- **可比的班级对比**：只比较两班都有有效作答的共同题，同时给出覆盖人数和得分的分母；同一班同一题同一评分点至少 2 人失分才算共性问题。
- **规则配置化**：推荐线索、追问题组匹配、掌握度阈值、导出样例和课程对照数据（教材页码、课标条目、前置关系）放在 `app/rules.json` 与 `app/catalog/curriculum.json`，可用 `STUDY_RULES` 指定覆盖文件。

### 4.2 可行性

- 依赖少：Python 3.11+、FastAPI、Uvicorn，默认完全离线运行。
- 数据量小：本地实跑覆盖40名学生、806行原始记录，使用SQLite保存批次和交互版本。
- 可复现：同一输入重复构建得到相同的诊断；成果包可重新构建。
- 可审计：质量报告保留原始异常、复核前后值和理由。

## 6. 运行条件与后续验证

| 条件 | 处理方式 |
|---|---|
| 单次测验有效作答少于三条 | 展示区间、证据条数和“证据不足”，安排补充观察 |
| 扩展题型或学科 | 补充规则、题组和测试后启用 |
| 追问反馈 | 与原题评分点并列展示，教师确认后安排新题复查 |
| 共享服务 | 配置账号、班级权限与HTTPS，按角色读取证据和计划 |
| 教师评价 | 已备18个案例和评分表，下一阶段收集独立评分并按案例统计 |
